# Ain 관세 인사이트 카드뉴스 디자인 스펙

대상: 네이버 블로그 "Ain 관세 인사이트" (아인합동관세사무소) 카드뉴스. 규격 1080x1350 (4:5), 7~8장.
구현: `template.html` + `cards.css` (HTML/CSS/vanilla JS, 외부 의존 없음). 데이터 구조는 `post-schema.md`. 렌더 확인은 `render.mjs` → `preview/card-0N.png`.

## 1. 디자인 방향 (rationale)

레퍼런스 리뷰의 결론은 "근원의 4:5 통일 + 조율의 쟁점·주장·판단 구조 + 근거 고정"이었다. 그래서 이 시스템의 정체성은 장식이 아니라 **근거가 보이는 서류철(dossier)** 이다.

- 하나의 서체(Pretendard Variable), 하나의 베이스(남색 #0f172a), 카테고리당 강조색 1개. 사진·일러스트 없음.
- 모든 카드 네 모서리에 **등록 마크(corner marks)** 를 둔다. 서류·도면의 트림 마크처럼 "검증된 문서"라는 인상을 만드는 시리즈 서명이며, 유일한 상시 장식이다.
- 사건번호·조문·시행일은 어디서나 같은 모양의 **근거 칩(.evi)** 으로 표기한다. 독자는 칩 모양만 보고 "근거"임을 안다.
- 눈에 띄는 요소는 한 곳에만 쓴다: **판단 카드의 붉은 인장(seal)**. 로고의 붉은 점 색(#9a1b1e)을 그대로 쓰고, 결과어(기각 / 인용 / 취소 / 시행 중)를 -7도 기울인 사각 도장으로 찍는다. 세관 날인·결정문 인장이라는 업계 어휘에서 온 모티프라 다른 업종 템플릿과 혼동되지 않는다.
- 표지에는 **조문·사건번호 워터마크**(외곽선 글자, 우측으로 흘러나감)를 둔다. 글의 근거 자체를 비주얼로 쓰는 장치로, 토픽마다 달라져 표지가 서로 구분된다.
- 색은 남색·흰색·연청(#eff6ff) 세 바탕만 교대로 쓴다: 표지·판단(남색) / 결론·사실·비교·체크(흰색) / 쟁점·출처(연청). 넘길 때 리듬이 생기고, 어두운 카드가 "결론이 나오는 곳"임을 알려 준다.

## 3. 타입 스케일 (Pretendard Variable)

| 토큰 | 크기 / 행간 / 굵기 | 용도 |
|---|---|---|
| display | 84 / 1.22 / 800, 자간 -0.03em | 표지 제목 (2~3줄) |
| h1 | 64 / 1.25 / 800 | 카드 헤드라인 (판단, 체크리스트) |
| conclusion | 60 / 1.35 / 800 | 결론 한 문장 (강조어는 강조색 `<em>`) |
| h2 | 48 / 1.4 / 700~800 | 쟁점 질문, 비교 제목(42) |
| body | 38 / 1.55 / 500 | 본문 설명 (최소 34 준수) |
| small | 34 / 1.45~1.5 / 500~600 | 표·비교·체크 설명, 조문 인용 |
| meta | 28 / 1.3 / 600~800 | 칩, 시리즈, 페이지, 섹션 태그, 근거 칩 |
| 출처 본문 | 30 / 1.45 / 600 | 출처 카드 목록 (예외적으로 34 미만, 정보 밀도 때문) |
| 면책 | 26 / 1.45 / 500 | 출처 카드 하단 면책 문구만 |
| 인장 | 84 (2자) / 60 (3자 이상) / 900 | 판단 카드 결과어 |
| 워터마크 | 168 / 900, 외곽선 2 px 22% 흰색 | 표지 |

규칙: 한 카드의 본문은 약 60자 이내, 헤드라인 20자 이내. `word-break: keep-all` 로 어절 단위 줄바꿈. 날짜는 `2026. 1. 1.` 형식으로 통일하고 줄바꿈이 어색하면 `<span class="nowrap">`.

## 5. 카드 레이아웃 (8종)

공통: 상단 크롬 + 등록 마크 + 하단 크롬. `data-type` 으로 구분.

1. **cover (표지, 남색)**: 상단 워터마크(조문/사건번호, 외곽선) → 하단 정렬로 킥커(34, 날짜·구분) / 제목(84, 2~3줄) / 근거 칩 행(사건번호 또는 조문, 선고일 또는 시행일). 제목은 질문형 또는 결론형 20~28자.
2. **conclusion (결론 먼저, 흰색)**: 태그 "결론 먼저" → 중앙에 결론 문장(60, 강조어 2개 이내) + 주석(34) → 하단 괘선 위 `영향 대상 / 기준일` 정의 목록.
3. **facts (사실관계·배경, 흰색)**: 태그 → 리드 문장(38) → 키-값 표(220 px 라벨 열 + 값, 2 px 괘선). 행 3~5개. 값 안의 핵심(날짜·금액·세율)은 `<b>` 로 강조색.
4. **issue (쟁점과 근거, 연청)**: 태그 → 중앙에 질문(48) + 한 줄 답(38) → 하단 고정 조문 박스(흰 바탕, 좌측 10 px 강조 띠): 조문명(34/800), 메타 칩(시행일·법률번호), 인용문(34, 따옴표 강조색). 인용은 60자 이내로 "…" 생략.
5. **compare (비교, 흰색)**: 태그 → A 박스(회색 테두리) → 연결 표시(↓ 또는 vs) → B 박스(강조색 테두리 + 6% 틴트). `mode: "change"` 는 변경 전/후, `"parties"` 는 세관 vs 수입자(B에 판단이 채택한 쪽 또는 결론 측을 둔다). 각 박스: 라벨(28) / 제목(42) / 불릿 1~3개(34).
6. **ruling (판단·결정 요지, 남색)**: 태그 "판단" 또는 "요지" → 우상단 붉은 인장(결과어 2~4자) → 헤드라인(64, 폭 620 이내, 인장과 겹치지 않음) → 포인트 목록(○ 해당 / × 비해당, 38) → 하단 근거 칩(결정 조항·근거 조문).
7. **checklist (실무 체크리스트, 흰색)**: 태그 → 헤드라인 "우리 회사는 이렇게"(64) → 체크 항목 3개(제목 42/800 + 설명 34). 체크박스는 강조색 56 px. 하단 선택: 관련 글 칩.
8. **source (출처 + CTA, 연청)**: 태그 "출처" → 근거 박스(사건번호·결정일, 법령명·법률번호·시행일(강조색), "원문: law.go.kr 등") → 면책 문구 + 작성월 → 하단 남색 CTA(질문형 한 줄 + "아인합동관세사무소에 문의하세요" / aincustoms.com / 02-518-5435).

7장 구성이 필요하면 facts 를 issue 에 흡수(issue 의 `text` 에 배경 한 줄)하거나 compare 를 생략한다. 순서는 유지.

## 6. 해야 할 것 / 하지 말 것

Do
- 카드당 메시지 하나. 결론 카드에서 이미 답을 말하고, 뒤 카드는 근거를 쌓는다.
- 숫자·날짜·사건번호는 항상 근거 칩이나 `<b>` 강조로 "찾기 쉽게" 표시한다. 시행일은 출처 카드에 반드시 반복한다.
- 결과어는 결정문·판결문의 용어 그대로(기각, 인용, 취소, 시행 중). 인장은 ruling 카드 한 곳에만.
- 어두운 카드에서는 로고를 흰색 반전(`filter`)으로 쓴다. 로고 원본 색을 바꾸지 않는다.
- 렌더 후 `render.mjs` 의 overflow 검사 결과가 모두 `ok` 인지 확인하고 PNG 를 눈으로 본다.

Don't
- 스톡 사진·일러스트·그라데이션·그림자 장식 추가 금지. 아이콘은 체크·○·×·화살표·인장뿐.
- 한 카드에 강조색 두 가지 이상 금지(카테고리 색 + 인장 빨강이 같은 카드에 있지 않도록 ruling 카드의 칩은 흰색 반전).
- 본문 34 px 미만 금지(출처 카드 목록 30, 면책 26만 예외). 본문 60자·헤드라인 20자 초과 시 글을 줄인다. 글자 크기를 줄이지 않는다.
- 전체 대문자·중점(·) 나열·"01 02 03" 번호 장식 금지. 체크리스트는 번호 대신 체크박스.
- 특정 업체를 추정하게 하는 서술, 마스킹된 사건번호(OOO) 기재 금지. 미확인 URL 을 카드에 쓰지 않고 "원문: law.go.kr 등"으로 표기.
- 관세청 등 공식 카드뉴스를 재가공해 자체 제작처럼 보이게 하지 않는다.

## 7. 제작 절차

1. `template.html` 의 `window.POST` 를 토픽 데이터로 교체(`post-schema.md`).
2. `npm i playwright@1.64.0 --prefix <dir>` 및 `npx playwright@1.64.0 install chromium` 1회 → `PLAYWRIGHT_DIR=<dir> node render.mjs` → `preview/card-0N.png` 생성과 overflow 검사.
3. PNG 를 모바일 폭(약 400 px 로 축소)에서 다시 보고 가독성 확인 후 블로그 업로드. 본문에는 3줄 요약·근거 박스·면책·연락처를 실텍스트로 반복(검색 노출용).
