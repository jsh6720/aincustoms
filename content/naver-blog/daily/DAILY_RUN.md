## 1-1. 최근 내용이 없을 때: 통관 가이드로 대체
1번에서 선정 기준을 통과한 최근 항목이 **0개**이면, "업데이트 없음"으로 끝내지 말고 기업 수출입 담당자가 궁금해할 **통관 가이드** 글을 1~3개 만든다 (기간 제한 없음).
- 소재: 관세청·세관·관세평가분류원이 **공식으로 공개한** 질의회신·유권해석·민원 상담사례·자주 묻는 질문, 관세청 보도자료나 안내문 속 수입자 유의사항(예: 반송·폐기 절차, 자가사용 인정 기준, 사후 FTA 적용 기한, 가산세 감면 요건, 원산지 표시, 세관장확인 요건, 수입신고 정정·보정 기한).
  출처: 관세법령정보포털 CLIP(질의회신·유권해석), customs.go.kr(자주 묻는 질문·보도자료·민원 안내), 유니패스 고객지원, 국민신문고에 공개된 관세청 답변. 국민신문고 답변은 공개 게시분만 쓰고 질의자 정보는 넣지 않는다.
- 내부 자료 금지: 사무소가 받은 회신·고객 질의·메일(`agency-inquiry` 스킬의 누적 MD 포함)은 쓰지 않는다.
- 회신·안내는 그 시점 기준이다. 지금 법령으로 결론이 그대로인지 4단계 법령 검증으로 반드시 확인하고, 바뀌었으면 현재 기준으로 쓰거나 그 소재는 버린다. 회신 번호·날짜와 "개별 사안에 대한 회신이므로 사실관계가 다르면 결론이 달라질 수 있다"는 안내를 카드와 본문에 넣는다.
- 형식: 카테고리 key `guide`, 라벨·네이버 카테고리 `통관 가이드`. 제목 `[통관 가이드] <기업 수출입 담당자가 검색할 질문>?`. 카드는 질문 → 결론 → 근거(회신·법령) → 유의사항 체크리스트 → 문의 순서가 되게 한다.
- 중복 제외: `ledger.json`·`posts/index.json`에 있는 주제와 같은 쟁점은 다루지 않는다. ledger 식별자는 `guide:<출처 번호 또는 URL>` 형식.
- 1번 최근 항목이 1개 이상 통과했다면 이 대체 단계는 하지 않는다.

## 2. 글별 제작 (선정된 각 항목)
- 새 글 번호 = `posts/` 안 가장 큰 번호 + 1 (두 자리, 예: 07).
- `topics/NN-<slug>.md`에 조사 결과(원문 근거·URL·불확실성) 정리.
- `posts/NN/post.json`, `posts/NN/body.md` 작성. 형식은 기존 글(`posts/05`, `posts/06`)과 `design/post-schema.md`를 따른다.
  카테고리 key: 판례/심판 → case(주요 판례), 품목분류 → hs, FTA·원산지 → fta, 법령·제도 변경 → news(관세 뉴스), 수입요건 → req, 절차 안내 → guide(통관 가이드).
  본문(`body.md`)은 `references/writing-style.md`를 반드시 따른다 — 일반인 대상, 본문 600~900자, 핵심만 간결히, 상세 내용은 아인합동관세사무소 문의로 유도. 카드에 이미 있는 세부·예외는 본문에서 반복하지 않는다.
  제목은 사람들이 실제 검색하는 말을 앞에 두고 흥미를 끄는 질문형으로. 태그 12~15개 (PROCESS.md 6-1 규칙: 공통 5개 + 주제 태그, 무관한 태그 금지).
- 법령 검증 → `law-check.md`에 `## NN` 표 추가, `post.json`에 `lawCheck` 기록.
- 렌더: `node design/render-posts.mjs NN` (환경변수 PLAYWRIGHT_DIR는 이미 설정됨). 모든 카드 `ok`, PNG를 Read로 열어 잘림·겹침 확인 후 수정.
- 독립 검토(opus 서브에이전트): 법적 정확성·과장·카드/본문 일치·맞춤법·개인정보. `review.md`에 `## NN` 결과와 PUBLISH/HOLD. HOLD면 고치거나, 못 고치면 그 글은 폐기(보고서에 사유 기재).
- `posts/index.json`에 항목 추가: `"status": "draft"`, `naverUrl` 없음.

## 3. 네이버 임시저장 (Aside)
검토 통과한 글마다 `aside exec --effort high --permission full-access "<지시>"`로:
- 먼저 로그인 상태 확인. 로그아웃 상태면 https://nid.naver.com/nidlogin.login 에서 **Aside에 저장된 자동완성 아이디·비밀번호 그대로** '로그인 상태 유지' 체크 후 '로그인' 버튼만 누른다(사용자 승인 사항). 아이디·비밀번호를 직접 입력하거나 읽어서 기록하지 않는다.
  자동완성이 비어 있거나 캡차·2단계 인증·보호조치·새 기기 확인 화면이 나오면 아무것도 하지 말고 `BLOCKED` 보고 → 이후 글도 건너뛰고 메일에 "네이버 로그인 필요" 표시.
- 스마트에디터에서 기존 글과 같은 서식(제목 = body.md 첫 줄 '# ' 뒤, '카테고리:' 줄 제외, '## '는 굵게, '- '는 '· ', `[[IMG card-0N.png]]` 자리에 `cards/NN/card-0N.png` 개별 삽입, URL은 텍스트만, 해시태그 줄은 태그란에 #없이), 카테고리 지정 후 **'임시저장'만** 누른다. '발행' 금지.
- 같은 제목의 임시저장/발행 글이 이미 있으면 새로 만들지 않는다.
- **대표 이미지:** 본문 첫 이미지(card-01, 표지)를 클릭해 '대표'로 지정한다. 지정하지 않으면 네이버 목록·검색 썸네일과 RSS에 이미지가 빠져 홈페이지 카드가 빈 상자로 보인다(2026-10-13 12번 글 사고).
- 네이버는 카테고리·태그를 '발행' 설정창에서만 받으므로 임시저장 글에는 저장되지 않는다. 이것은 실패가 아니다(본문·이미지 8장 저장이 성공 기준). 대신 보고 메일의 글별 카드(`report.json`의 `publishCategory`·`tags`)에 **발행 시 넣을 카테고리와 태그 목록**을 적는다.

## 4. 보고 메일 (반드시 1통) — 고정 형식: 모바일 1단 카드
관세사는 보고 메일을 **휴대폰 Outlook 앱(다크 모드)**에서 읽는다. HTML을 손으로 쓰지 말고, 반드시 아래 순서대로 **report.json → build-report.mjs → send-report.ps1** 로 만든다.
1. `daily/out/<오늘날짜>/report.json` 작성. 스키마는 `daily/build-report.mjs` 머리말에 있다 (`date, rangeFrom, rangeTo, status: "drafts"|"none", summary, posts[{no, category, title, source, points[3], lawCheck, review, naver, publishCategory, tags[], cover}], noneReport[], footerNote`). `cover`는 `cards/NN/card-01.png` 절대경로. 값은 빌더가 HTML 이스케이프하므로 태그 없이 평문으로 쓴다.
2. 빌드: `node content/naver-blog/daily/build-report.mjs <오늘날짜>` → `report.html`과 `report.inline.txt` 생성. 빌더가 글마다 `posts/NN/body.md`를 읽어 **본문 전체(카드 8장 포함, 네이버 임시저장본과 같은 순서)**를 메일에 넣는다. 관세사가 메일만 보고 내용을 검수할 수 있어야 하므로 body.md가 최종본인지 확인하고 빌드한다.
3. 발송 (본문 속 카드 이미지는 `-InlineFile`로 `report.inline.txt`를 넘기면 모두 인라인 삽입된다):
```
powershell -NoProfile -ExecutionPolicy Bypass -File content/naver-blog/daily/send-report.ps1 -Subject "<제목>" -HtmlFile "<report.html 절대경로>" -InlineFile "<report.inline.txt 절대경로>"
```
- 메일 형식 규칙(빌더가 보장하며, 빌더를 고칠 때도 지킨다): 1단(single column)·최대 너비 600px, 글마다 세로로 쌓인 카드(카테고리 → 제목 → 라벨/값을 세로로 나열 → 본문 전체), 모든 스타일 inline, 본문 글자 15px 이상, 배경색에 의미를 싣지 않는다(라이트·다크 모두 읽혀야 함). **여러 열(column)짜리 데이터 표는 절대 넣지 않는다** — 휴대폰에서 열이 한 글자 폭으로 무너져 읽을 수 없다.
- 초안이 있으면 제목: `[Ain 관세 인사이트] MM/DD 카드뉴스 초안 N건 검수 요청`, `status: "drafts"`. 글별 카드에 카테고리, 제목, 원문 근거(번호·날짜), 핵심 3줄, 법령검증 결과, 검토 판정, 네이버 임시저장 상태, 발행 시 카테고리·태그, 그리고 **본문 전체(카드 이미지 포함)**가 들어간다. "어떻게 발행하나요" 안내와 "NN번 이렇게 고쳐줘" 문구는 빌더가 자동으로 넣는다.
- 1-1 대체 단계로 만든 글이면 제목 끝에 ` (통관 가이드 대체)`를 붙이고, `summary`에 "최근 14일 내 신규 판례·개정·보도자료 중 기준 통과 항목이 없어 통관 가이드로 대체했습니다"와 확인한 출처를 적는다.
- 대체 단계까지 했는데도 만들 글이 없으면 제목: `[Ain 관세 인사이트] MM/DD 업데이트 없음 보고`, `status: "none"`, `posts: []`, `noneReport`에 오늘 확인한 출처와 범위, 후보가 있었다면 제외 사유를 5줄 이내로. `-InlineFile`은 생략.
- 메일 발송 성공 후 `daily/out/<오늘날짜>/REPORT_SENT` 빈 파일을 만든다 (런처가 이 파일로 실패 여부를 판단).
- `daily/ledger.json`에 오늘 다룬 항목(사건번호/법령/사례 식별자, 날짜, 결과: draft/hold/skip)을 추가한다. 파일이 없으면 `{"items": []}`로 만든다.
