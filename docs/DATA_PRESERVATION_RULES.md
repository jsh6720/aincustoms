# 운영 데이터 불변 규칙

이 문서는 축산물 통관 대시보드의 기능을 수정할 때 기존 체크, 날짜, 요청, 메모,
수취 및 전달 상태를 유지하기 위한 필수 규칙이다.

## 핵심 원칙

1. 화면·레이아웃·기능 수정은 기존 운영 데이터를 변경하지 않는다.
2. API의 부분 업데이트는 요청에 명시된 필드만 저장한다.
3. 누락된 필드를 `false`, 빈 문자열, `null` 또는 기본 날짜로 바꾸지 않는다.
4. 새 컬럼이 아직 없는 환경의 폴백 조회는 실제로 없는 새 컬럼만 제외한다.
5. 서로 다른 계정에 연결된 동일 화물은 필드별 이력을 병합한다. 다른 필드의
   `updated_at`이 더 최근이라는 이유로 기존 O 상태를 X로 바꾸지 않는다.
6. 명시적인 O→X 변경은 해당 기능의 저장 API가 연결된 모든 현재 행에 같은 값을
   기록할 때만 반영한다.
7. 로컬 폴더 동기화는 화물 원천 데이터만 갱신한다. 홈페이지에서 입력한 체크,
   날짜, 요청, 메모 및 관리자 상태를 초기화하지 않는다.

## 서류전달 최초 입력시각 보존

- 삼현전달·창고전달의 O 전환 시각은 서버 시각으로 저장하고 화면에서는
  한국시간으로 표시한다.
- 이미 O인 연결 행에 입력일 또는 입력시각이 있으면 재저장·계정 전파 시 기존
  최초 값을 유지한다. 이후 동기화 시각이나 다른 필드의 `updated_at`으로
  덮어쓰지 않는다.
- O에서 X로 명시적으로 전환할 때만 해당 전달일과 전달시각을 함께 비운다.
- timestamp 컬럼이 없는 환경에서는 timestamp 필드만 요청에서 제외하고 기존
  날짜 컬럼은 계속 저장한다.
- 기존 O 행의 timestamp가 비어 있어도 임의 시각을 역산하거나 채우지 않는다.
  이 경우 기존 날짜만 사용자에게 표시한다.

## 구현 규칙

- `cargo_card_user_inputs` 조회 컬럼은
  `lib/cargo-user-input-query.js`의 단일 목록에서 관리한다.
- 마이그레이션 호환 폴백은 오류에 명시된 신규 컬럼 그룹만 제외한다. 현재 허용된
  그룹은 `TRANSPORT_CONFIRMATION_COLUMNS`와
  `DOCUMENT_DELIVERY_DATE_COLUMNS`이며, 기존 체크·날짜·요청 필드는 유지한다.
- 서류전달 상태는 연결된 행 중 O 이력이 하나라도 있으면 O로 병합한다.
- 서류전달을 명시적으로 X로 바꾸는 API는 모든 연결 행을 X로 전파한다.
- 필드별 운송정보 편집은 화면에 표시한 필드만 API에 전송한다. 숨겨진 입항예정일,
  프리타임, 반입구역 또는 반입예정일 값을 함께 전송해 기존 값을 덮지 않는다.
- 새로운 체크나 날짜 필드를 추가할 때는 다음 테스트를 먼저 추가한다.
  - 기존 O/날짜가 무관한 최신 수정으로 사라지지 않는 테스트
  - 부분 업데이트가 다른 필드를 보존하는 테스트
  - 마이그레이션 전 폴백이 기존 필드를 계속 조회하는 테스트
- 계정 유형별 열 표시·숨김은 CSS와 렌더링에서만 처리한다. 숨겨진 열의 화물,
  요청, 서류, 날짜 및 상태 값은 수정하거나 삭제하지 않는다.
- 비밀번호는 `pgcrypto` 해시로만 저장하고 관리자 화면이나 API 응답에 원문 또는
  해시를 노출하지 않는다. 관리자는 비밀번호 조회 대신 재설정만 수행한다.
- 새 계정 분류를 추가하는 마이그레이션은 `shipper_accounts`의 계정 설정만
  변경하며 `cargo_cards`와 `cargo_card_user_inputs`의 기존 행을 갱신하지 않는다.

## 변경 이력 관리 규칙

- 기능·오류·화면 수정은 `docs/CHANGE_REQUEST_HISTORY.md`에 날짜별로 누적한다.
- 기존 요구사항을 대체하더라도 과거 기록은 삭제하지 않고 변경 사유와 새 규칙을
  별도 항목으로 추가한다.
- 운영 데이터에 영향을 줄 수 있는 변경은 이 문서의 보존 규칙과 회귀 테스트를
  동시에 갱신한다.
- 문서 갱신 없이 기능 작업을 완료 또는 배포 완료로 처리하지 않는다.

## 배포 전후 검증

1. 변경 전 Supabase의 해당 필드별 O 개수와 주요 BL 값을 읽기 전용으로 기록한다.
2. 전체 자동화 테스트를 실행한다.
3. 배포 후 동일 값을 다시 조회해 개수와 주요 BL이 유지되는지 확인한다.
4. 화면 API에서 기존 O/날짜/요청이 동일하게 반환되는지 확인한다.
5. 차이가 있으면 자동 보정하지 말고 배포를 중지하고 원인을 먼저 조사한다.

## 수입신고 진행 자동 알림 보존

- 자동 알림 발송 여부는 카드 행이나 연결 계정의 상태로 추측하지 않고 `cargo_status_notifications.event_key` 원장으로 판정한다.
- HCH 한 B/L의 `수입신고`와 `수입(사용소비) 심사진행`은 동일 이벤트 키를 사용하여 상태 변경 순서와 관계없이 한 번만 발송한다.
- 도입 당시 이미 신고진행인 HCH 카드는 기준선 이벤트를 먼저 기록해 과거 메일을 막고, 이후 신규 B/L은 이전 카드 행이 없더라도 최초 신고진행 관측을 알림 대상으로 처리한다.
- 카드 재동기화, 연결 계정 생성, 상태 문구 변경은 이미 `sent`인 원장을 삭제하거나 `pending`으로 되돌리지 않는다.
- 실패 재시도는 기존 원장의 `attempt_count`, `last_attempt_at`, `error_message`만 갱신하며 새 이벤트를 만들지 않는다.
- 알림 기능 장애나 마이그레이션 미설치가 기존 카드·수기 입력·서류 상태 동기화를 중단시키지 않게 한다.

## 복구 원칙

- DB에 기존 값이 남아 있으면 데이터를 다시 쓰지 않고 조회·병합 코드를 수정한다.
- 실제 값이 사라진 경우에만 감사 가능한 대상 목록을 만든 뒤 복구한다.
- 복구 SQL 또는 스크립트는 실행 전후 행 수와 변경 대상 BL을 출력해야 한다.

## 관세청 자동 상태와 수동 상태 보존

- 관세청 검역 합격 자동 상태는 표시 우선순위로만 적용하고 관리자 수동 △/X 값을
  덮어쓰거나 삭제하지 않는다.
- API는 관세청 원문, 관세청 자동 합격 여부, 관리자 수동 상태를 각각 분리해
  반환한다.
- 관세청 합격 정보가 더 이상 조회되지 않으면 저장된 관리자 수동 상태가 다시
  화면에 표시되어야 한다.
- 자동 합격 상태는 읽기 전용이며 관리자 토글 저장 API를 호출하지 않는다.
- 자동 합격 판정 원본은 `prgs_stts`와 `cscl_prgs_stts`이며, 사용자 입력행이 없는
  카드에도 동일한 판정 규칙을 적용한다.
- 동물검역과 식품검역은 관세청 상세 진행이력 전체에서 각각 누적 판정한다. 최신
  진행상태가 다른 검역 합격으로 변경되어도 이미 확인된 합격을 `△` 또는 `X`로
  되돌리지 않는다.
- 로컬 분석 결과의 관세청 누적값과 관리자 수동 표시값은 별도 필드로 유지하며,
  동기화 과정에서 수동 표시값이 관세청 누적값을 덮어쓰지 않게 한다.
- Supabase 동기화는 기존 `합격`과 현재 관세청 합격 문구를 누적 병합한다. 수동
  `△`/`X` 또는 구버전 서버 응답만으로 기존 관세청 합격을 하향 변경하지 않는다.

## 양도증 수기 상태 보존

- 관리자 양도증 O/X 토글은 `transfer_received_override`만 변경한다.
- 토글 저장 시 OBL 수취 여부, H/C 수취 여부 및 실제 원본서류 수령일을 함께
  읽어 기존 값 그대로 전송하며, 양도증 변경 때문에 다른 필드가 초기화되지
  않게 한다.
- 양도증 수기 변경일은 `linked-account-sync` 행보다 실제 관리자 수기 변경행의
  `updated_at`을 우선 사용한다.
- 연결 계정 간 양도증 상태는 동일하게 전파하되, 전파 작업 시각으로 원래 수기
  변경일을 덮지 않는다.
- 폴더 스캔 결과와 수기 override를 별도 보존하고, 수기 override가 존재하면
  화면에는 해당 값을 우선 표시한다.

## 서류전달 날짜 컬럼 호환 및 상태 보존

- 삼현/창고 서류전달 저장은 날짜 컬럼 누락 때문에 O/X 상태 저장까지 차단하지
  않는다.
- 날짜 컬럼 누락 오류 시 `docs_delivered_samhyeon_date`,
  `docs_delivered_warehouse_date`만 제거하여 재시도한다.
- 호환 재시도에서는 전달 O/X와 요청에 명시된 필드만 저장하며, 다른 체크 상태와
  기존 날짜를 null로 덮어쓰지 않는다.
- 연결 계정 전파 대상과 기존 전달 상태 병합 규칙은 날짜 컬럼 유무와 관계없이
  동일하게 유지한다.

## 연결 계정 읽기 범위와 입력 격리

- 연결 계정 공통 상태를 병합할 때는 현재 로그인 계정의 입력 행만 조회해서는 안 된다.
- 동일한 원본 폴더와 B/L로 연결된 계정의 공통 상태 행을 읽고, O 이력이 하나라도 있으면 O를 유지한다.
- 전체 입력 행을 읽더라도 운송정보, 검역, 스티커, 숨김 등 계정별 입력은 카드의 `account_id`와
  정확히 일치하는 행만 적용한다.
- 공통 상태 병합을 위한 조회 범위 확대를 다른 계정의 수기 입력 복사 또는 데이터 초기화로 사용하지 않는다.

## 역할별 메일 설정 및 미리보기 보존

- 역할별 기본 메일 주소는 `ain_default`, `shipper_default`, `destination_default`로
  별도 저장하며 기존 기능별 메일 설정 행을 삭제하거나 덮어쓰지 않는다.
- 역할별 설정이 비어 있거나 마이그레이션 전이면 기존 기능별 설정과 환경변수의
  실제 적용 주소를 대체 기본값으로 사용한다.
- 요청 메일과 변경 안내 메일의 To/CC 방향만 조합하며, 카드·요청·서류 상태 또는
  운송정보를 메일 주소 설정 작업에서 갱신하지 않는다.
- 발송 전 미리보기 API는 메일 본문과 수신처만 계산하고 DB 저장 또는 SMTP 발송을
  수행하지 않는다.
- 사용자가 미리보기를 취소하면 운송정보 저장과 메일 발송을 모두 수행하지 않는다.
