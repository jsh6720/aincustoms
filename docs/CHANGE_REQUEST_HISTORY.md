# Cargo Dashboard Change Request History

이 문서는 축산물 통관 대시보드의 누적 요구사항과 유지해야 할 동작을 기록한다.
새 기능을 수정할 때에는 이 문서와 관련 회귀 테스트를 함께 갱신한다.

## 누적 변경 관리 절차

- 모든 기능 추가, 동작 수정, 오류 수정은 작업을 완료하기 전에 이 문서에 누적한다.
- 기존 항목을 삭제하거나 현재 구현에 맞춰 몰래 덮어쓰지 않는다. 요구가 변경된 경우
  이전 규칙과 변경된 규칙을 날짜별로 모두 남긴다.
- 체크·날짜·요청·메일·메모·권한·동기화처럼 운영 데이터를 다루는 변경은
  `docs/DATA_PRESERVATION_RULES.md`에도 보존 규칙을 추가하거나 기존 규칙과의
  일치 여부를 확인한다.
- 변경 내용을 보호하는 회귀 테스트를 함께 추가하고 전체 테스트 통과 후 배포한다.
- 배포 후 실제 운영 화면에서 변경 동작과 기존 핵심 동작을 모두 확인한다.
- 작업 완료 보고에는 변경 이력 반영 여부, 테스트 결과, 배포 커밋을 포함한다.

## 2026-07-30 - 서류전달 입력일 및 운송정보 필드별 편집

- 삼현전달·창고전달을 O로 변경한 날짜를 각각 별도 컬럼에 저장하고, X로
  되돌리면 해당 날짜만 초기화한다.
- 동일 화물의 연결 계정에서는 각 전달 상태를 O로 만든 행의 날짜를 함께
  병합하며, 다른 계정의 무관한 최신 X 행이 날짜를 지우지 않게 한다.
- BL 진행현황의 삼현·창고 O에 마우스를 올리면 저장된 입력일을 확인한다.
- 입항예정일, 반입(예정)구역, 반입예정일 셀을 클릭하면 선택한 필드만
  편집하는 전용 창을 표시한다.
- 필드별 전용 저장에서는 보이지 않는 운송정보를 API에 전송하지 않는다.
  전체 운송정보 편집 버튼을 사용할 때만 기존 전체 입력창을 유지한다.
- 서류전달 날짜 컬럼이 아직 없는 Supabase에서도 기존 로그인과 통관 조회가
  중단되지 않도록 날짜 컬럼만 제외한 호환 조회를 사용한다.
- `반입예정일` 셀은 운영 화면에서도 `반입예정일 입력` 전용 창을 열어야 하며,
  입항예정일·프리타임·반입구역 입력란을 함께 표시하거나 전송하지 않는다.
- 운영 배포 커밋 `2c0b2fc`에서 구버전 DB 호환 조회를 추가했고, 전체 자동화 테스트
  174개와 실제 운영 화면의 전용 입력창을 확인했다.

## 2026-07-29 - 기존 체크 보존 및 서류전달 표시 복구

- Supabase에 남아 있는 삼현전달·창고전달 O 값을 마이그레이션 호환 폴백에서도
  계속 조회하도록 수정한다.
- 연결 계정의 무관한 최신 수정 행이 기존 서류전달 O를 X로 덮지 않도록 필드별
  병합으로 변경한다.
- `cargo_card_user_inputs` 조회 컬럼을 단일 모듈에서 관리하고, 폴백은 실제로 없는
  확정 컬럼만 제외한다.
- 모든 후속 수정은 `docs/DATA_PRESERVATION_RULES.md`의 운영 데이터 불변 규칙을
  따른다.

## 유지 원칙

- 로컬 동기화로 통관 데이터가 갱신되어도 화주/관리자가 입력한 확인사항, 할당관세, 운송정보, 요청 이력은 유지한다.
- 동일 화물의 화주 계정과 납품처 계정은 연결된 상태값을 일관되게 표시한다.
- API 조회값과 수기 입력값은 출처와 우선순위를 구분하고, 오래된 값이 최신 값을 덮지 않게 한다.
- 관리자 전용 기능은 서버 API에서도 권한을 검사한다.
- 홈페이지, 로컬 연동 사본, Vercel 패키지 사본은 배포 전 동일성 검사를 수행한다.
- Vercel Hobby 플랜의 서버리스 함수 제한을 넘기지 않도록 기존 API를 우선 확장한다.

## 화면과 진행상태

- 앱 제목은 `AIn 축산물 통관조회`로 표시한다.
- 대시보드는 입항전, 입항, 반입, 수입신고, 반출 마일스톤을 사용한다.
- 수입신고 단계는 신고진행과 신고수리를 구분한다.
- 진행상태는 카드에서 강조해 표시한다.
- 반출 중량 정보는 반출 마일스톤 카드에서만 표시한다.
- 전량 반출 후 7일까지 카드를 유지하고 그 이후 기본 현황에서 숨긴다.
- 관리자 숨김과 영구 제외 이력을 구분한다.
- BL별 진행현황은 기본 진입 화면으로 사용할 수 있으며 대시보드 메뉴로 전환할 수 있다.
- BL별 진행현황 정렬은 `납품처명`, `입항(예정)일`, `마일스톤`, `BL` 순서다.
- 마일스톤 오름차순은 `입항전`, `입항`, `반입`, `수입신고`, `반출`이다.

## 카드 입력과 확인사항

- 확인사항은 카드별 여러 항목으로 저장하며 수정, 완료, 권한별 삭제를 지원한다.
- 확인사항이 있는 카드를 우선 배치하고 눈에 띄는 음영을 적용한다.
- 화주가 작성한 확인사항은 화주 본인이 삭제할 수 있다.
- BL 진행현황의 BL 호버에서 관리자/화주 확인사항을 조회하고 입력할 수 있다.
- 할당관세 대상 여부와 추천서 교부일을 카드 안에서 관리한다.
- 할당관세 경고 및 수입신고 기한은 붉은색으로 강조한다.
- 운송정보는 인도조건, 입항예정일, 장치장, 프리타임 일수, 보세창고 입고예정일을 관리한다.
- 프리타임은 기본 3일이며 입항일 당일을 포함해 만기일을 계산한다.

## 서류와 검역

- OBL, H/C 원본 수취 여부와 수령일을 관리한다.
- BL, IV, PL, H/C, C/O, 보험, 운임, 양도증 파일 존재 여부를 폴더 규칙에서 자동 인식한다.
- 문서 파일 O/X는 로컬 스캔 결과이며 임의 토글로 덮어쓰지 않는다.
- 원본 O/X를 해제할 때 확인 절차를 거친다.
- OBL 선사 접수일을 관리자와 모바일 화면에서 저장하며 연결 계정에 동일하게 반영한다.
- BL 진행현황의 원본 서류 열은 `OBL 접수일`, `BL원본`, `H/C원본`, `양도증` 순서로 연속 배치한다.
- 동물검역과 식품검역은 `O`, `△`, `X`를 지원한다.
- 유통이력은 본인/본레스 신고번호를 선택 입력하고 번호를 복사 가능한 팝업으로 표시한다.
- 서류전달은 삼현전달과 창고전달 O/X를 관리한다.

## 요청과 메일

- 서류수령 요청은 입항전, 입항, 반입 단계에서 활성화한다.
- 수입신고 요청은 입항, 반입 단계에서 활성화한다.
- 출고 요청은 전량/일부 중량과 담당자, 주소, 일자, 요청사항을 지원한다.
- 요청자 이메일은 선택사항이며 입력 시 참조(CC)로 발송한다.
- 반입예정구역/반입예정일을 화주가 변경할 때 저장만 또는 저장 후 메일을 선택한다.
- 원본 수령 확인과 OBL 접수 확인 메일은 추가 수신인을 지원한다.
- 기능별 공통 메일 수신처를 관리자 설정에서 관리한다.
- 화주 계정에 요청메일 우선 수신처가 있으면 공통 수신처보다 우선 적용한다.
- 공통 설정이 비어 있으면 기존 환경변수/기본 수신처를 사용한다.

## 계정과 필터

- 로그인 아이디는 대소문자를 구분하지 않는다.
- 관리자, 화주, 납품처, 전체조회 계정을 구분한다.
- 각 계정은 부여된 필터에 해당하는 화물만 조회한다.
- 관리자 계정은 전체 화물과 설정 화면을 조회한다.
- 납품처 계정의 입력 출처는 `납품처`로 표시한다.
- 화주 화면에서는 관리자 전용 동물검역, 식품검역, 유통이력 관리 열을 숨긴다.

## 달력

- BL 일정 달력은 이전/다음 월과 연도를 이동할 수 있다.
- 기본 표시 일정은 서류요청일, 서류수령일, 입항예정일이다.
- 수입신고 요청일과 반입예정일은 계정별 표시 설정으로 켜고 끌 수 있다.
- OBL/H/C 수령은 같은 날짜에 `(OBL, H/C)`로 구분한다.
- 양도증 수령일은 진행현황 달력에서 제외한다.
- 전량 반출로 기본 현황에서 숨긴 카드도 이력과 달력 데이터는 유지한다.

## 2026-07-26 기능별 메일 설정 및 OBL 입력 개선

- 관리자 설정에 기능별 To/CC 수신처를 추가한다.
- 설정 기능은 서류수령 요청, 수입신고 요청, 출고 요청, 반입정보 변경 알림,
  원본서류 수령 확인, OBL 접수 확인으로 구분한다.
- 공통 설정을 기본으로 사용하고 화주별 요청메일 수신처가 있으면 우선 적용한다.
- OBL 접수일은 `MMDD`, `YYMMDD`, `YYYY-MM-DD` 입력을 허용한다.
- `MMDD`는 현재 연도, `YYMMDD`는 2000년대로 해석한다.
- OBL 접수일 바로 오른쪽에 BL 원본 열을 배치한다.
- BL 진행현황 정렬 기준을 회귀 테스트로 고정한다.

## 2026-07-27 입항 일정 OBL 원본 상태 표시

- BL 진행현황 하단 캘린더의 입항 일정에 OBL 원본 수취 상태를 함께 표시한다.
- OBL 원본 수취 상태가 `true`이면 `입항 {BL번호} (OBL O)`로 표시한다.
- OBL 원본 수취 상태가 `false`이거나 값이 없으면 `입항 {BL번호} (OBL X)`로 표시한다.
- 입항일 산정, 캘린더 색상, 정렬 및 필터 동작은 변경하지 않는다.

## 2026-07-27 화주 요청 완료 상태 표시

- 서류수령 화주요청이 있고 OBL 원본이 수령되면 `서류수령 요청/수령O`로 표시한다.
- 수입신고 화주요청이 있고 실제 신고가 진행되면 `수입신고 요청/진행O`로 표시한다.
- `수입신고전`은 신고 진행으로 간주하지 않는다.
- 완료된 요청 배지는 초록색 음영으로 구분하되 기존 요청 상세 호버는 유지한다.
- 테스트용 수입신고 요청 데이터는 운영 데이터에서 삭제한다.

## 2026-07-27 서류전달 열 관리자 전용화

- BL별 진행현황의 `서류전달` 열은 관리자 계정에서만 표시한다.
- HCH 화주 계정과 CTF 납품처 계정을 포함한 일반 계정에서는 헤더와 행 셀을 모두 숨긴다.
- 기존 삼현전달/창고전달 상태와 관리자 토글 기능은 유지한다.

## 2026-07-27 관리자 진행현황 레이아웃 복구

- 관리자 화면은 모든 관리 열이 읽히도록 진행현황 표의 최소 너비를 `2280px`로 유지한다.
- 화주 및 납품처 계정은 관리자 전용 열이 숨겨진 만큼 `1980px` 너비를 사용한다.
- 전체조회 계정은 숨겨지는 열 수에 맞춰 `1760px` 너비를 사용한다.
- 관리자 화면에 더 작은 `1860px` 너비를 강제해 셀 내용이 세로로 깨지던 역전 CSS 규칙을 제거한다.

## 2026-07-27 관리자 공통 상태 연결 계정 동기화

- 스티커요청, 동물검역, 식품검역, 수입신고, 유통이력 및 서류전달 상태는 같은 원본 폴더를 조회하는 연결 계정에 함께 저장한다.
- 스티커요청은 운송정보 갱신 시각으로 대표값을 선택하지 않고 B/L 공통 상태로 병합한다.
- 연결 계정 값이 과거 데이터에서 일시적으로 다르면 스티커요청 `O`를 보존하고, 이후 관리자 변경 시 모든 연결 행을 같은 값으로 정리한다.
- OBL 접수와 서류전달에서 사용하던 연결 대상 탐색도 동일한 공통 함수로 유지한다.

## 2026-07-27 모바일 화주 서류수령 요청 우선 표시

- 모바일 원본서류 수취관리에서 화주가 서류수령을 요청한 B/L을 상단에 우선 배치한다.
- 미수령 화주 요청을 가장 먼저 표시한다.
- 화주 요청이 없는 건 중 입항·반입 단계이며 OBL 또는 H/C가 미수령인 B/L을 두 번째로 표시한다.
- 일반 B/L은 그다음, `요청/수령O` 상태인 완료 요청은 맨 마지막에 표시한다.
- 요청 상태는 `화주 수령요청` 또는 `요청/수령O` 배지로 구분하고 희망 수령일을 함께 표시한다.
- 같은 요청 그룹에서는 최신 요청이 먼저 보이며 검색 결과에도 같은 우선순위를 적용한다.

## 2026-07-28 원본서류 재요청 허용

- 화주는 마일스톤과 관계없이 OBL 또는 H/C 원본 중 하나라도 미수령이면 서류수령을 요청할 수 있다.
- OBL과 H/C 원본이 모두 수령된 카드만 서류수령 요청을 비활성화한다.
- 기존 요청이 있으면 최근 요청담당자, 요청인 메일, 수령요청일 및 요청사항을 팝업에 불러와 수정 후 다시 요청할 수 있다.
- 재요청은 기존 요청을 덮어쓰지 않고 새 요청 이력으로 저장한다.
- 홈페이지 진행현황, 대시보드 카드 및 저장 API가 같은 수취 상태 규칙을 사용한다.

## 2026-07-31 관세청 검역 합격 자동 우선 표시

- 관세청 화물 진행상태에 `검사/검역 동물검역(합격)`이 확인되면 동물검역 상태를
  관리자 수동 △/X보다 우선하여 읽기 전용 `O`로 표시한다.
- 관세청 화물 진행상태에 `검사/검역 식품의약품(합격)`이 확인되면 식품검역 상태를
  관리자 수동 △/X보다 우선하여 읽기 전용 `O`로 표시한다.
- 자동 표시된 `O`에 마우스를 올리면 `관세청 확인`을 표시한다.
- 관세청 합격 원문과 수동 상태를 별도 보존하며, 관세청 합격 정보가 사라지면 기존
  수동 상태가 다시 표시된다.
- 이 변경은 화면/API 병합 규칙만 변경하며 Supabase 마이그레이션이나 데이터 갱신을
  수행하지 않는다.

### 2026-07-31 자동 판정 데이터 원본 수정

- 실제 관세청 합격 문구는 검역 요약 필드가 아니라 `prgs_stts`와
  `cscl_prgs_stts`에 있으므로 두 진행상태 원문을 합쳐 판정한다.
- `animal_quarantine`, `food_quarantine`의 일반 `합격` 값만으로는 자동 O를
  판정하지 않는다.
- 화주 입력행 존재 여부와 무관하게 모든 카드에 관세청 자동 판정 필드를 붙인다.
- 기존 관리자 수동 △/X와 기타 카드 데이터는 갱신하거나 삭제하지 않는다.

### 2026-07-31 동물·식품검역 합격 이력 누적 보존

- 관세청 상세 진행이력에서 동물검역과 식품검역 합격을 각각 독립적으로 누적한다.
- 최신 진행상태가 한 종류의 합격 문구로 바뀌더라도 과거에 확인된 다른 종류의
  합격 상태를 잃지 않는다.
- 로컬 카드에는 관세청 누적값을 수동 표시값과 분리하여 보존하고, 홈페이지
  동기화는 관세청 누적값을 우선 전송한다.
- 홈페이지는 최신 진행상태와 누적 검역 필드를 함께 판정하여 둘 중 어느 한쪽에서
  합격이 확인되면 해당 검역을 읽기 전용 `O`로 표시한다.
- 예약 동기화는 Supabase의 기존 합격값과 현재 관세청 진행문구를 `(계정, BL)`별로
  병합하여, 서버 프로세스 재시작 전에도 이미 확인된 합격이 하향 변경되지 않게
  한다.
- 관리자 수동 △/X는 삭제하거나 덮어쓰지 않으며, 관세청 합격 표시와 별도로
  보존한다.
