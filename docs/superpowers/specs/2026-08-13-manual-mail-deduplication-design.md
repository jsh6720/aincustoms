# 모바일 OBL 처리 및 수동 메일 중복 방지 설계

## 목표

- 모바일 원본서류 화면에서 화주 요청 건 다음으로 `OBL 수령 O / 선사 미접수` 건을 배치한다.
- OBL 선사 접수메일 팝업은 접수일이 비어 있을 때만 한국 기준 오늘 날짜를 기본 입력한다.
- 수령메일과 OBL 접수메일의 UI 및 서버 action을 분리하고 재클릭을 막는다.
- 모든 수동 메일의 동일 업무 내용 중복 발송을 서버에서 차단한다.

## 발송 키

`메일 유형 + 계정 + 정규화 B/L + 업무 입력값`을 정렬된 JSON으로 만든 뒤 SHA-256으로 해시한다.
같은 입력은 어느 API 인스턴스에서 처리하더라도 같은 키가 된다. 수령 서류 종류, 접수일,
요청일, 담당자, 물량, 변경 전후 운송정보처럼 실제 메일 의미를 바꾸는 값은 업무 입력값에 포함한다.

## 원자적 선점

Supabase `cargo_status_notifications`에 `manual_mail` 유형을 추가한다.
`claim_cargo_manual_mail` 함수가 고유 발송 키를 원자적으로 선점하며 첫 호출만 `claimed=true`를 받는다.
이미 `sent` 또는 `pending`이면 SMTP를 실행하지 않는다. 명시적으로 `failed` 처리된 건만 다시 선점할 수 있다.
SMTP 성공 후 `sent`, 실패 후 `failed`로 기록한다.

## 적용 범위

- 원본서류 수령 확인
- OBL 선사 접수 확인
- 원본서류 수령 요청
- 수입신고 요청
- 출고 요청
- 입항일 변경 안내
- 반입·입고예정 정보 변경 안내

자동 수입신고 진행 및 입고 일정 알림은 기존 이벤트별 중복 방지 구조를 계속 사용한다.
