# 관세청 검역 합격 자동 전환 설계

## 목표

관세청 화물 진행상태에 합격 문구가 조회되면 관리자 수동 검역 상태와 무관하게
해당 검역 상태를 자동 `O`로 표시하고, 상태 출처를 호버로 확인할 수 있게 한다.

## 판정 규칙

- 동물검역은 관세청 원문에 `검사/검역 동물검역(합격)`이 포함되면 자동 합격이다.
- 식품검역은 관세청 원문에 `검사/검역 식품의약품(합격)`이 포함되면 자동 합격이다.
- 공백과 줄바꿈 차이는 무시한다.
- `불합격`이나 다른 검역 종류의 합격 문구는 자동 합격으로 판정하지 않는다.

## 우선순위와 데이터 보존

- 관세청 자동 합격이 관리자 수동 `△/X`보다 표시 우선순위가 높다.
- 자동 합격 중에도 기존 수동 override 값은 삭제하거나 `O`로 덮어쓰지 않는다.
- 관세청 합격 문구가 더 이상 없으면 저장돼 있던 수동값을 다시 표시한다.
- 자동 합격 상태는 관리자도 클릭하여 변경할 수 없는 읽기 전용 `O`다.

## 데이터 흐름

1. `cargo_cards`의 관세청 원문 검역 상태를 API 응답의 별도 필드로 보존한다.
2. 공통 유틸리티가 검역 종류별 정확한 합격 문구를 판정한다.
3. 대시보드는 자동 합격 여부를 먼저 확인하고 자동 `O`를 렌더링한다.
4. 자동 `O`에는 `title="관세청 확인"`을 부여한다.
5. 자동 합격이 아니면 기존 수동 `O/△/X` 동작을 그대로 사용한다.

## 오류 처리

- 관세청 원문이 비어 있거나 문자열이 아니면 자동 합격이 아니다.
- API 응답에 신규 자동 상태 필드가 없더라도 기존 검역 상태 표시는 유지한다.
- 데이터베이스 마이그레이션은 필요하지 않다.

## 검증

- 동물검역 합격 문구만 동물검역을 자동 `O`로 만든다.
- 식품의약품 합격 문구만 식품검역을 자동 `O`로 만든다.
- 불합격 및 서로 다른 검역 종류의 문구는 자동 `O`가 되지 않는다.
- 수동 `△/X`가 있어도 관세청 합격이 우선 표시된다.
- 자동 `O`에는 `관세청 확인` 호버가 있고 토글 버튼은 없다.
- 전체 회귀 테스트와 운영 HTML 반영을 확인한다.
