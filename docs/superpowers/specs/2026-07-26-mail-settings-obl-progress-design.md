# 기능별 메일 설정, OBL 입력, 진행현황 정렬 설계

## 목표

관리자가 홈페이지 설정에서 메일 기능별 공통 수신처를 관리하고, 기존 화주별
요청메일 수신처를 선택적 우선값으로 유지한다. BL별 진행현황에서는 OBL 접수일
입력을 간소화하고 열 배치와 정렬 기준을 명시적으로 고정한다.

## 메일 설정

`public.cargo_mail_settings` 테이블에 기능별 설정을 한 행씩 저장한다.

- `original_doc_request`: 서류수령 요청
- `import_request`: 수입신고 요청
- `release_request`: 출고 요청
- `warehouse_change`: 반입정보 변경 알림
- `original_doc_receipt`: 원본서류 수령 확인
- `obl_carrier_receipt`: OBL 접수 확인

각 행은 `to_recipients`, `cc_recipients`, `updated_at`, `updated_by`를 가진다.
수신처는 쉼표/세미콜론/줄바꿈으로 입력하며 서버에서 유효한 이메일만 정규화한다.

기존 `/api/cargo-admin`을 확장한다.

- 관리자 GET 응답에 계정과 메일 설정을 함께 반환한다.
- `action = mail_settings` POST는 여섯 설정을 일괄 upsert한다.
- 기존 계정 저장 POST는 현재 동작을 유지한다.
- 관리자 권한 검사는 기존 세션 검사를 재사용한다.

발송 우선순위는 다음과 같다.

1. 요청형 메일은 화주 계정의 `release_request_to`
2. 해당 기능의 `cargo_mail_settings.to_recipients`
3. 기존 환경변수 또는 코드 기본값

CC는 기능별 공통 CC에 요청자 이메일 또는 화면에서 추가한 수신인을 병합하고
중복을 제거한다.

## 관리자 화면

기존 계정 관리 아래에 `기능별 메일 수신처` 영역을 추가한다. 여섯 기능을 행으로
표시하고 각 행에 받는 사람(To)과 참조(CC)를 둔다. `전체 저장` 버튼으로 한 번에
저장한다. 기존 계정의 `출고요청 메일 받는 사람`은 `요청메일 우선 수신처`로
명칭을 바꿔 세 요청 기능의 계정별 override임을 명확히 한다.

## OBL 접수일

브라우저 입력은 아래 형식을 ISO 날짜로 정규화한다.

- `0621` -> 현재 연도 `YYYY-06-21`
- `260621` -> `2026-06-21`
- `2026-06-21` -> 그대로 사용
- 기존 편의를 위해 `06-21`, `26-06-21`, 점/슬래시 구분도 허용

실존하지 않는 날짜는 거부한다. API에는 항상 `YYYY-MM-DD`만 전달해 기존 저장
계약을 유지한다. 모바일 OBL 접수 입력에도 같은 규칙을 적용한다.

## 열 배치

BL별 진행현황의 관련 열 순서는 다음과 같다.

`... 수입신고요청, OBL 접수일, BL원본, 동물검역, 식품검역, 유통이력, ... BL파일, IV, PL, H/C파일, H/C원본 ...`

즉 기존 문서 묶음 안에 있던 BL원본을 OBL 접수일 바로 오른쪽으로 이동한다.

## 정렬

정렬 키는 다음 우선순위를 사용한다.

1. 납품처명: 폴더명 구분자 `_` 앞의 명칭, 한국어 오름차순
2. 입항(예정)일: 실제 입항/세관 입항일 우선, 이후 수기 ETA, API 최초반입일
3. 마일스톤: 입항전, 입항, 반입, 수입신고, 반출
4. BL 번호

날짜가 없는 화물은 같은 납품처의 날짜 있는 화물 뒤에 둔다. 기존 브라우저 정렬과
공유 유틸리티의 기준을 일치시키고 회귀 테스트로 고정한다.

## 호환성과 장애 대응

- 새 메일 설정 테이블이 아직 적용되지 않았거나 비어 있어도 기존 수신처로 발송한다.
- 새 API 파일을 만들지 않아 Vercel 서버리스 함수 제한을 유지한다.
- 이메일 비밀번호와 서비스 키는 DB나 브라우저로 노출하지 않는다.
- 홈페이지 소스 검증 후 로컬 연동 사본과 Vercel 패키지 사본에 동일 파일을 반영한다.

## 검증

- 메일 설정 마이그레이션 및 관리자 권한 테스트
- 수신처 우선순위와 To/CC 병합 테스트
- OBL 날짜 형식 및 유효하지 않은 날짜 테스트
- 납품처/날짜/마일스톤/BL 복합 정렬 테스트
- OBL 접수일 다음 BL원본 열 배치 마크업 테스트
- 전체 Node 테스트와 로컬 Python 회귀 테스트
