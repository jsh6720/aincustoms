# 관리자 계정 추가 및 다우린 납품처 계정 설계

## 목표

관리자 설정에서 신규 계정 생성 기능을 쉽게 찾고 사용할 수 있게 한다. 다우린을 납품처 계정으로 등록해 화물의 납품처명이 `다우린`일 때 기본 이메일 `ocm3800@hyundaicorp.com`이 안내메일 수신인에 자동 포함되게 한다.

## 관리자 화면

- 관리자 설정 상단 작업 영역에 `+ 계정 추가` 버튼을 추가한다.
- 버튼을 누르면 기존 계정 입력 폼을 신규 작성 상태로 초기화하고 폼으로 스크롤한 뒤 아이디 입력란에 초점을 둔다.
- 기존 계정 목록의 수정 버튼, 기능별 메일 설정과 저장 흐름은 변경하지 않는다.
- 신규 계정 저장이 성공하면 목록을 다시 불러와 생성 결과를 즉시 확인할 수 있게 한다.

## 다우린 계정

- 로그인 아이디: `DWR`
- 초기 비밀번호: `dwr1234`
- 권한: `shipper`
- 입력 구분: `destination`
- 표시명: `다우린`
- 필터텍스트: `다우린`
- 기본 이메일: `ocm3800@hyundaicorp.com`
- 사용 상태: 활성

다우린 계정 생성 SQL은 `login_id`를 기준으로 멱등 처리한다. 이미 계정이 있으면 중복 생성하지 않고 위 계정 설정을 갱신하되, 기존 행의 식별자는 유지한다.

## 데이터 흐름

관리자 화면의 신규 계정 저장은 기존 `/api/cargo-admin`과 `admin_upsert_shipper_account` RPC를 재사용한다. 안내메일 주소 결정은 기존 회사명 매칭 로직을 재사용하므로, 카드 납품처명이 `다우린`으로 정규화되면 다우린 계정의 기본 이메일이 받는 사람에 포함된다.

## 오류 처리와 보존

- 아이디와 신규 비밀번호가 없으면 기존 검증 메시지를 표시한다.
- 납품처 계정의 필터텍스트가 없으면 저장하지 않는다.
- 기존 계정, 화물 카드, 메일 설정은 삭제하거나 초기화하지 않는다.
- 비밀번호는 화면이나 API 응답에 평문으로 반환하지 않는다.

## 테스트

- 관리자 화면에 명확한 계정 추가 버튼이 있고 신규 폼 초기화 함수를 호출하는지 검증한다.
- 신규 계정 API가 `destination` 분류와 기본 이메일을 RPC에 전달하는지 검증한다.
- 다우린 마이그레이션이 지정된 계정값과 중복 방지 처리를 포함하는지 검증한다.
- 다우린 카드의 안내메일 수신인에 `ocm3800@hyundaicorp.com`이 포함되는 회사명 매칭 회귀 테스트를 실행한다.
