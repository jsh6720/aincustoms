# 서류전달 입력일 호버 설계

## 목적

BL별 진행현황의 `서류전달` 열에서 삼현전달과 창고전달이 `O`인 경우,
마우스를 올리면 해당 상태가 `O`로 입력된 날짜를 확인할 수 있게 한다.

## 데이터 모델

`cargo_card_user_inputs`에 다음 날짜 컬럼을 추가한다.

- `docs_delivered_samhyeon_date date`
- `docs_delivered_warehouse_date date`

기존 행 전체의 `updated_at`은 다른 상태 변경에도 갱신되므로 전달 입력일로
사용하지 않는다. 각 전달 상태와 날짜는 연결된 화주·납품처 계정의 동일 BL에
함께 저장한다.

## 저장 규칙

- 삼현전달 또는 창고전달을 `X`에서 `O`로 변경하면 한국 날짜 기준 당일을
  해당 날짜 컬럼에 저장한다.
- `O`에서 `X`로 변경하면 해당 날짜 컬럼을 `null`로 초기화한다.
- 이미 `O`인 과거 데이터는 정확한 최초 입력일을 알 수 없으므로
  마이그레이션 실행일을 임의로 채우지 않는다.
- 다른 관리자 상태나 운송정보 변경은 서류전달 날짜를 변경하지 않는다.
- 연결 계정 병합 시 상태 `O`와 그 상태를 만든 날짜를 같은 원본 행에서
  선택하여 서로 다른 행의 상태와 날짜가 섞이지 않게 한다.

## 화면 표시

- 삼현전달 또는 창고전달이 `O`이고 입력일이 있으면 토글에 마우스를 올렸을 때
  `입력일 YYYY-MM-DD`를 표시한다.
- `X`이거나 과거 `O` 데이터에 날짜가 없으면 입력일 호버를 표시하지 않는다.
- 기존 O/X 토글, 확인창, 관리자 전용 열, 표 너비는 유지한다.

## 오류 처리

- 날짜 컬럼이 아직 생성되지 않은 환경에서는 저장 API가 실행해야 할 Supabase
  마이그레이션 파일명을 명확히 안내한다.
- 날짜 저장 실패 시 화면을 성공 상태로 바꾸지 않고 기존 O/X 상태를 유지한다.

## 검증

- 상태별 날짜 저장 및 초기화 API 테스트
- 연결 계정 상태·날짜 병합 테스트
- `O`일 때만 `입력일` 호버가 렌더링되는 소스 테스트
- 기존 서류전달 O/X 보존 테스트와 전체 테스트 실행
- 운영 배포 후 실제 토글의 호버 문구와 레이아웃 확인
