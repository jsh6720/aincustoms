# BL 진행현황 확정 표시 및 확인사항 팝업 개선 설계

## 목표

BL별 진행현황에서 관리자가 입항예정일, 반입예정구역, 반입예정일을 확정 상태로 관리하고, 확정된 셀을 빨간 테두리로 구분한다. BL 확인사항 팝업은 마우스를 팝업 안으로 이동해도 유지되며 기존 확인사항을 같은 팝업에서 수정할 수 있어야 한다.

## 권한

- 관리자만 운송정보의 확정, 확정취소, 확정값 변경을 수행한다.
- 화주, 납품처, 전체조회 계정은 확정 상태와 확정값을 읽기만 한다.
- 확인사항 추가와 수정은 기존 카드 화면 및 `/api/cargo-revision`의 쓰기 권한 규칙을 그대로 사용한다.
- 전체조회 계정은 확인사항을 읽기만 한다.

## 저장 모델

`cargo_card_user_inputs`에 다음 boolean 컬럼을 추가한다. 기본값은 `false`다.

- `eta_date_confirmed`
- `storage_yard_confirmed`
- `warehouse_expected_date_confirmed`

기존 운송정보 컬럼은 그대로 사용한다.

- 입항예정일: `eta_date`
- 반입예정구역: `storage_yard`
- 반입예정일: `warehouse_expected_date`

확정 상태는 브라우저 임시 저장소나 별도 JSON 필드에 저장하지 않는다.

## 확정 동작

관리자가 세 셀 중 하나를 누르거나 호버 팝업을 열면 현재 값이 입력된 간결한 편집 창을 표시한다.

- `저장`: 값을 저장하고 해당 필드의 확정 상태를 `false`로 만든다.
- `확정`: 입력값을 저장하면서 해당 필드의 확정 상태를 `true`로 만든다.
- `확정취소`: 값은 유지하고 확정 상태만 `false`로 만든다.
- 빈 값을 확정하려는 경우 저장하지 않고 입력을 요청한다.

확정 상태가 `true`인 셀은 역할과 관계없이 빨간 테두리와 옅은 빨간 배경을 사용한다. 화주와 납품처 화면에서는 편집 버튼 없이 확정 표시만 보인다.

## 연결 계정 일관성

같은 화물이 화주 계정과 납품처 계정에 각각 존재할 수 있으므로, 정규화된 B/L 번호와 동일한 원본 폴더로 연결되는 행에는 운송정보 값과 확정 상태를 함께 반영한다. 연결되지 않은 동명 B/L이나 다른 원본 폴더에는 전파하지 않는다.

로컬 동기화는 확정 상태를 덮어쓰지 않는다. 중복 행 병합 시 가장 최신 운송정보 갱신 시각의 값과 확정 상태를 함께 선택한다.

## API

새 서버리스 함수를 만들지 않고 기존 `/api/cargo-quota`의 `manual_fields` 작업을 확장한다.

- 관리자 요청에서만 확정 필드를 허용한다.
- 화주나 납품처가 확정 필드를 보내면 무시하지 않고 권한 오류를 반환한다.
- 값만 변경하는 일반 저장은 해당 필드의 확정을 해제한다.
- 확정 상태 변경도 `transport_updated_at`, 입력 역할, 로그인 ID를 갱신한다.
- 기존 비교 후 저장 및 충돌 방지 동작을 유지한다.

`/api/cargo-data`는 새 확정 컬럼을 조회하고 카드 데이터에 병합한다. 마이그레이션 전 환경은 명확한 마이그레이션 파일명을 안내한다.

## BL 확인사항 팝업

팝업은 BL 텍스트의 hover/focus로 열린다.

- BL에서 팝업으로 포인터가 이동해도 열린 상태를 유지한다.
- BL과 팝업 모두에서 포인터가 벗어나면 짧은 지연 후 닫는다.
- 팝업 내부 입력, 버튼, 텍스트 선택 중에는 닫지 않는다.
- 바깥 클릭과 `Escape` 키로 닫는다.
- 키보드 포커스가 팝업 내부에 있는 동안 유지한다.

기존 확인사항에는 작은 `수정` 버튼을 표시한다.

- 수정 버튼을 누르면 해당 행이 입력창과 `저장`, `취소` 버튼으로 바뀐다.
- 수정 초안은 카드와 B/L을 구분하는 키로 보존한다.
- 저장 성공 후 데이터를 다시 읽고 같은 B/L 팝업을 다시 연다.
- 취소 시 원문을 복원하고 팝업은 유지한다.
- 출력값과 HTML 속성값은 기존 escaping 규칙을 사용한다.

## 테스트

- BL에서 팝업으로 포인터를 이동할 때 닫히지 않는 이벤트 단위 테스트
- 바깥 이동, 바깥 클릭, `Escape`에서 닫히는 테스트
- 기존 확인사항 수정 렌더링 및 PUT payload 테스트
- 관리자만 확정 상태를 저장할 수 있는 API 테스트
- 세 확정값의 저장, 취소, 값 변경 시 자동 해제 테스트
- 연결 계정 전파 및 다른 원본 폴더 격리 테스트
- 확정 셀의 빨간 테두리 렌더링 테스트
- 관리자, 화주, 납품처, 전체조회 역할별 테이블 정렬 회귀 테스트
- 전체 Node 테스트와 배포 패키지 함수 수 제한 테스트

## 배포

홈페이지 원본, 로컬 연동 사본, Vercel 패키지 사본의 SHA-256을 일치시킨다. 마이그레이션 SQL은 `supabase/migrations`에 추가하고 사용자가 Supabase SQL Editor에서 실행할 수 있도록 별도 안내한다. 코드 배포는 GitHub `main` 푸시 후 Vercel 상태와 운영 페이지 마커를 확인한다.
