# 원본서류 재요청 활성화 설계

## 목표

화주 또는 납품처 계정에서 B/L의 OBL 또는 H/C 원본이 하나라도 미수령이면 마일스톤과 관계없이 원본서류 수령 요청을 보낼 수 있게 한다. 과거 요청이 있는 B/L도 최근 요청 내용을 불러와 요청일과 내용을 변경한 뒤 다시 요청할 수 있어야 한다.

## 원인

- 진행현황과 API가 원본서류 요청을 `입항전`, `입항`, `반입` 단계로 제한한다.
- 실제 반입 후 통관 진행으로 `수입신고` 마일스톤으로 이동한 B/L은 OBL이 X여도 버튼이 잠긴다.
- 기존 서류요청 팝업은 최근 요청일과 요청사항을 불러오지 않고 빈 값으로 초기화한다.
- 보드 카드의 요청 처리 조건에는 `반입`이 빠져 있어 진행현황과 동작이 다르다.

## 활성화 규칙

- OBL 또는 H/C 중 하나라도 미수령이면 서류수령 요청 버튼을 활성화한다.
- OBL과 H/C가 모두 수령된 경우에만 비활성화한다.
- 마일스톤은 활성화 판단에 사용하지 않는다.
- 화면과 서버 API가 같은 규칙을 사용한다.

## 재요청 규칙

- 최근 요청이 있으면 요청담당자, 요청인 메일, 수령요청일자, 요청사항을 팝업 기본값으로 불러온다.
- 사용자는 값을 변경해 다시 요청할 수 있다.
- 재요청은 기존 행을 덮어쓰지 않고 새 요청 이력으로 저장해 이전 기록을 보존한다.
- 저장 후 최신 요청 정보가 진행현황과 모바일 화면에 표시된다.

## 범위

- 홈페이지 진행현황 요청 버튼
- 대시보드 보드 카드 요청 버튼
- 원본서류 요청 팝업 기본값
- 원본서류 요청 API 검증
- 홈페이지 및 로컬 배포용 HTML 복사본
- 회귀 테스트와 변경 이력

## 검증

- 수입신고 단계이면서 OBL X인 카드의 요청 버튼이 활성화되는지 확인한다.
- OBL O, H/C X인 카드도 활성화되는지 확인한다.
- OBL O, H/C O인 카드만 비활성화되는지 확인한다.
- 기존 요청의 날짜와 요청사항이 팝업에 다시 채워지는지 확인한다.
- API가 단계와 무관하게 미수령 카드 요청을 받고, 모두 수령된 카드 요청은 거절하는지 확인한다.
