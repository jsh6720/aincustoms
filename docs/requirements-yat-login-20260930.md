# YAT 로그인 점검 — 2026-09-30

## 확인된 범위

- `/requirements/`와 공개 JS는 정상 응답하며 www 없는 주소도 www로 이동한다.
- 현재 runtime-config의 Apps Script API는 무인증 조회를 UNAUTHORIZED로 거절한다.
- 실제 고객 계정이 아닌 무작위 진단용 아이디의 로그인 1회 역시 UNAUTHORIZED를 반환했다. 실제 YAT 로그인 성공 여부를 뜻하지 않는다.
- 사용자 제보는 `Invalid credentials`. 현재 배포된 클라이언트/서버 오류 문구와 달라 실제 접속 URL 및 캐시 여부 확인이 필요하다.
- DB 직접 읽기는 401로 거절됐고, 브라우저/Computer Use 연결은 시간 초과했다. 계정 관련 원본 검색은 자격증명 노출 우려로 안전 검토에서 차단되어 중단했다. 실제 계정의 비밀번호를 조회하거나 초기화하지 않았다.

## 로컬 수정

- 서버 장애, 네트워크 오류, 잘못된 자격증명, 시도 제한을 서로 다른 안내로 표시한다.
- 로그인 진행 중 중복 제출을 막고, 실패 시 다시 입력할 수 있게 한다.
- 토큰이나 사용자명이 없는 성공 응답을 세션으로 저장하지 않는다.
- 서버 원문/예외 객체를 화면·콘솔에 노출하지 않는다. 화주별 권한, 계정 DB, 비밀번호 검증 규칙은 변경하지 않는다.
- 새 회귀 시험과 API 클라이언트 시험 29개 통과. 기존 auth-ui 시험 15개 중 14개 통과, 수정 전부터 있던 `logout, expiry, and replacement login scrub all prior-user UI`는 사전 자료 렌더 단계에서 계속 실패한다.

## 미완료

YAT 및 다른 실제 화주의 로그인·회사별 조회 검증, 원인 확정, 운영 배포는 미완료다. 실제 계정 접근이 확보되기 전에는 위 UI 수정으로 YAT 인증 문제가 해결됐다고 판단하면 안 된다. 접근 확보 시 비밀번호/토큰 출력 없이 계정의 활성 여부, 중복 아이디, 해시/솔트 존재 여부를 확인하고, 한 번의 정당한 로그인과 회사별 읽기 권한을 검증한다. 비밀번호를 추측하거나 인증을 우회하지 않는다.
