# 2026-09-14 모바일 원본서류·선사접수 묶음 메일

사용자 요청: 모바일 원본 수령 안내가 양도증으로 표시되는 원인을 수정하고, 같은 날짜의 원본 수령과 선사접수를 B/L 여러 건당 한 통으로 발송한다. 선사접수는 선사명·묶음명과 선택 B/L로 나눌 수 있도록 한다. 작업 위치는 AIN 통합 프로그램으로 지정되었다.

## 원인과 변경

기존 화면은 카드의 OBL/H/C/양도증 O 상태에서 메일 종류를 자동 결정했다. 양도증만 O인 경우 제목과 본문이 양도증 안내가 되었다. 발송 후 저장은 선택에 관계없이 OBL/H/C를 모두 O로 변경했다.

새 모바일 흐름은 OBL 기본 선택, H/C 명시 선택을 사용한다. 양도증 상태는 안내 서류 종류를 결정하지 않는다. 이전 클라이언트가 양도증을 수령 서류로 전송하면 400으로 거절하고 새로고침을 안내한다.

1. 상단 '원본 수령 묶음 메일' 또는 '선사접수 묶음 메일' 선택
2. 실제 날짜·화주 선택, 선사접수는 선사명과 선택적 묶음명 입력
3. B/L 선택; 검색을 바꾸어도 선택 유지, 날짜·화주 변경 시 선택 초기화
4. 원본 수령은 이번에 받은 OBL/H/C와 묶음 전체 페이지 입력
5. 실제 적용 수신처·제목·본문·B/L 전체를 미리보기
6. 'N건 · 메일 1통 발송'으로 확정

서류 수령과 선사접수는 서로 다른 업무이므로 각각 한 통으로 묶는다. 같은 날 같은 선사의 일부 B/L만 보내고 남은 B/L은 다른 묶음으로 처리할 수 있다. 선사명은 사용자가 확인하여 입력하며 B/L 접두어로 추측하지 않는다.

## 상태 보존과 중복 차단

- 기존 원장 RPC claim_cargo_manual_mail/settle_cargo_mail을 사용한다. 새 테이블·컬럼·SQL 마이그레이션은 없다.
- B/L과 원본 폴더, 업무 종류, 날짜, 수령 서류 종류로 안정적인 중복 키를 만든다. 폴더가 없는 경우 계정도 식별에 포함한다.
- 묶음명·메모·선택 순서·페이지 변경으로 같은 서류를 재발송할 수 없다.
- OBL을 먼저 안내한 뒤 같은 날 H/C만 추가 수령한 경우 H/C 안내는 가능하다.
- 겹친 B/L/서류가 있으면 전체 묶음을 발송하지 않고 충돌 항목을 표시한다. 자동으로 일부만 보내지 않는다.
- 실제 SMTP는 묶음당 한 번 호출한다. 발송 결과가 불명확하거나 일부 수신처만 접수되면 자동 재발송을 차단한다.
- 수령 저장은 이번에 선택한 OBL/H/C만 O로 부분 업데이트하고 기존 실제수령일, 양도증, 다른 입력을 유지한다.
- 선사접수 저장은 해당 필드만 연결계정에 전파한다.
- 메일 발송 후 상태 저장 실패는 실패 B/L을 표시한다. 다시 메일을 보내지 말고 상태만 저장하도록 안내한다.
- 미리보기는 읽기만 한다. 취소 시 발송·원장 claim·상태 저장이 없다.
- 최대 50 B/L, 독립 조회와 상태 저장은 5개 제한 병렬 처리. claim은 정렬 순서를 유지하며 조회가 길어지면 SMTP 전에 중단한다.

## 검증

- 기능·상태·모바일 회귀시험 34개 통과.
- 모바일 Chrome 390x844 합성자료 시험: 미리보기 발송 0회, 원본 3건당 SMTP mock 1회, MSC 2건당 mock 1회, 남은 ONE 1건 별도 표시, 검색 선택 유지, JavaScript 오류 0, 가로 넘침 0.
- 홈페이지 전체 원본: 492개 중 448통과/44실패.
- 수정본: 519개 중 475통과/44실패. 기존 실패 이름 44개가 완전히 동일하고 새 실패는 없다. 기존 요건관리 테스트 문제를 이번 메일 변경에서 수정하지 않았다.
- 실제 고객 메일, 운영 DB 쓰기 및 NEWMAIN 서비스 시작·종료는 시험에서 수행하지 않았다.
- 독립 리뷰에서 서류별 키, 연결계정 변동에 안정적인 키, 지원하지 않는 서류 거절, UI 상태, 시간 제한을 개선했다.

## 2026-09-14 추가 지시: OBL 기본·필수

사용자가 모든 서류 접수 메일에 OBL 접수를 기본으로 진행하도록 명시했다. 이전 H/C 단독 발송 설계를 대체한다. 모바일에서는 OBL을 해제할 수 없는 필수 항목으로 표시하고 H/C만 추가 선택한다. 서버도 OBL 없는 명시 요청을 400으로 거절한다. 이미 안내한 OBL을 같은 날짜에 재포함하면 기존 중복 차단을 유지한다. 관련 시험 35개 통과, 실제 브라우저에서 H/C 추가 및 미리보기 확인. 테스트 화면은 가상 자료와 메모리 원장만 사용하며 실제 SMTP·운영 DB를 호출하지 않는다. 운영 배포는 계속 승인 대기다.

## 2026-09-14 추가: 요청 목록 한정과 미리보기 표시

원본서류 수령 묶음 메일과 선사접수 묶음 메일에는 last_original_doc_request 또는 last_original_doc_request_id가 있는 화물만 표시한다. 개별 카드에서 요청 없는 화물을 넣는 동작도 차단한다. 미리보기 시 전체 페이지 미입력은 해당 입력란으로 이동해 안내하고, 성공하면 제목·수신처·본문의 시작으로 스크롤한다. 테스트 화면에는 가상 페이지 수를 채우고 두 종류의 메일 미리보기 버튼을 제공한다. 관련 시험 37개 통과; 실제 Chrome에서 두 미리보기와 요청 없는 가상 B/L 제외를 확인했다. 실제 발송·운영 DB 변경·운영 배포 없음.

## 2026-09-14 추가: B/L별 수령 페이지 수

기존 일괄 페이지 입력을 B/L별 입력으로 변경했다. 각 선택 건의 total_pages를 검증하고 B/L 정렬 뒤에도 페이지 수를 해당 건에 유지한다. 메일 상단에는 9, 10, 12 page (아래 B/L 순서), 각 B/L 상세에는 해당 페이지 수를 표시한다. 관련 시험 39개 통과 및 Chrome 미리보기에서 세 건의 페이지 일치 확인. 실제 발송 및 운영 배포 없음.
